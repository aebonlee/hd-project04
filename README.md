# 브라질/인도법인 CKD 컨테이너 수량 산출 자동화

> 🌐 **배포 페이지: [https://aebonlee.github.io/hd-project04/](https://aebonlee.github.io/hd-project04/)** · 저장소: https://github.com/aebonlee/hd-project04

브라질·인도 법인의 **18개월 생산계획(엑셀)**, **모델별 CKD 박스 구성**, **박스 규격 마스터**를
입력받아 40ft 컨테이너 적재 규칙(목표 적재율 70%)에 따라 **월별 필요 컨테이너 수량을 자동
산출**하고, 물류팀 전달용 엑셀로 내보내는 도구입니다.

- 기획: 김은수 (생성형 AI 업무자동화 전문가과정 1차수)
- 배경: CKD 선적 담당자가 과거 실적 감각으로 컨테이너 수량을 예측 → 과다 예측 시 미사용
  컨테이너 페널티, 과소 예측 시 선적 불가로 법인 매출 실패 발생. 이를 규칙 기반 자동 산출로 대체.

빌드 과정 없이 브라우저에서 바로 실행되며(GitHub Pages 배포 가능), 계산 로직은 UI와 분리된
순수 JS 모듈로 Node에서 단위 테스트됩니다.

## 2. 산출 규칙 상세

### 2.1 박스 소요 집계

월별·법인별 박스 종류별 필요 수량:

```
필요 박스 수(법인, 월, 박스) = Σ_모델 ( 생산 대수(법인, 모델, 월) × 대당 박스 수량(모델, 박스) )
```

### 2.2 1차 산출 — 단순 부피 기준

```
컨테이너 수(1차) = ceil( 총 부피(CBM) ÷ ( 컨테이너 CBM × 적재율 ) )
```

중량 기준 소요( `ceil(총 중량 ÷ (최대 중량 × 적재율))` )도 참고치로 함께 계산합니다.
1차 산출은 혼적 제약을 무시한 하한선이며, 실제 확보 수량은 2차 산출을 따릅니다.

### 2.3 2차 산출 — 적재 조합 (bin-packing 근사)

40ft 컨테이너에 함께 실을 수 있는 박스 종류가 한정되어 있으므로, **First-Fit Decreasing(FFD)**
근사 bin-packing으로 컨테이너별 적재 구성을 만듭니다.

1. 박스를 **혼적 그룹**별로 나눈다 — *같은 혼적 그룹끼리만 한 컨테이너에 적재*.
2. 그룹 내 박스를 부피 내림차순(동률이면 중량 내림차순)으로 정렬.
3. 박스를 하나씩, **먼저 열린 컨테이너 중 들어갈 수 있는 첫 컨테이너**에 적재.
   들어갈 컨테이너가 없으면 새 컨테이너 개설.
4. 컨테이너별 한도:
   - 부피 한도 = 컨테이너 CBM × 적재율 (기본 67.7 × 0.70 = 47.39 CBM)
   - 중량 한도 = 최대 적재 중량 × 적재율 (기본 26,780 × 0.70 = 18,746 kg)

결과로 컨테이너 한 대 한 대의 박스 구성과 실적재율(부피/중량)이 산출되며, UI의
"컨테이너별 적재 구성 내역"과 내보내기 엑셀의 월별 상세 시트에서 검증할 수 있습니다.

### 2.4 남는 박스 처리 (이월)

- **기본**: 남는 박스 없이 **해당 월에 컨테이너를 추가 확보**하여 전량 선적.
- **이월 옵션**(`carryOver`): 그룹별 마지막(가장 덜 찬) 컨테이너의 부피 사용률이
  임계값(`carryOverThreshold`, 기본 50%) 미만이면 그 박스들을 **다음 달로 이월**.
  마지막 달은 전량 선적합니다. UI 체크박스로 켜고 끌 수 있습니다.

### 2.5 가정 (기획서 5번 — 규칙 확정 전 기본값)

실무 규칙이 확인되면 `config/container.json`과 박스 마스터만 수정하면 됩니다(코드 수정 불필요).

1. **적재율 기본 70%** — 부피·중량 양쪽 한도에 동일 적용하며 설정/슬라이더로 변경 가능.
2. **혼적 규칙** — 확인 전까지 "같은 혼적 그룹끼리만 한 컨테이너" + "부피·중량 한도"로 가정.
3. **컨테이너는 40ft 단일 타입 가정** — 40HC는 옵션으로 선택 가능(설정에 규격 포함).
4. 적층 가능 단수는 데이터로 보유하되, 현 산출에는 부피·중량 한도에 흡수된 것으로 가정
   (3차원 배치 검증은 확장 항목).
5. 선적 리드타임(생산월 대비 선적 요청월 오프셋)은 0으로 가정 — 실무 오프셋이 확인되면
   월 컬럼을 선적 요청월 기준으로 맞춰 업로드하면 됩니다.

## 3. 사용법

### 3.1 실행

- 웹: GitHub Pages 배포 주소 접속, 또는 로컬에서 `index.html`을 브라우저로 열기
  (차트/엑셀 라이브러리는 `lib/`에 로컬 동봉되어 있어 인터넷 연결이 필요 없습니다.
  단, `file://`로 직접 열면 `config/container.json`을 읽지 못해 내장 기본값으로
  동작하며 화면에 안내 배너가 표시됩니다).
- 로컬 서버 실행 예: `python3 -m http.server 8000` → `http://localhost:8000`

**샘플 데이터 불러오기** 버튼을 누르면 업로드 없이 전체 기능을 바로 확인할 수 있습니다.

### 3.2 업로드 파일 컬럼 형식 (첫 번째 시트 기준)

**① 생산계획** (`plan_브라질.xlsx`, `plan_인도.xlsx` — 여러 파일 동시 선택 가능):

| 법인 | 모델명 | 2026-09 | 2026-10 | … | 2028-02 |
|---|---|---|---|---|---|
| 브라질 | R210-BR | 34 | 36 | … | 41 |

- 월 컬럼 헤더는 `YYYY-MM` 텍스트 형식이어야 합니다. 18개월이 아니어도 되며,
  `YYYY-MM` 형식의 컬럼은 모두 인식합니다.
- 같은 법인 파일을 다시 올리면 해당 법인 계획이 교체됩니다.

**② 모델-박스 구성** (`model_box.xlsx`):

| 모델명 | 박스코드 | 대당 박스 수량 |
|---|---|---|
| R210-BR | BX-A | 1 |

**③ 박스 마스터** (`box_master.xlsx`):

| 박스코드 | 길이(mm) | 폭(mm) | 높이(mm) | 부피(CBM) | 중량(kg) | 적층 가능 단수 | 혼적 그룹 |
|---|---|---|---|---|---|---|---|
| BX-A | 2300 | 2200 | 2200 | 11.132 | 3200 | 1 | G1 |

- `부피(CBM)`이 비어 있으면 치수(길이×폭×높이)로 자동 계산합니다.

### 3.3 산출 조건

- **목표 적재율**: 슬라이더/숫자 입력(50~95%) — 변경 즉시 재계산.
- **컨테이너 타입**: 40ft 일반 / 40HC (규격은 `config/container.json`).
- **남는 박스 처리**: 당월 추가 확보(기본) ↔ 다음 달 이월.

### 3.4 결과 화면

1. KPI 카드: 총/법인별 컨테이너, 월평균, 평균 실적재율.
2. 법인별 × 월별 컨테이너 소요 차트(18개월).
3. 월별 컨테이너 소요 표 — 2차(조합, 확보 기준)·1차(단순)·평균 실적재율.
4. 박스 종류별 물량 차트.
5. 적재율 시나리오(65/70/75%) 비교 차트 + 요약 표.
6. 컨테이너별 적재 구성 내역(월 단위 접기/펼치기, 검증용).
7. **엑셀 내보내기**: `요약` 시트(월별·법인별 소요/실적재율/시나리오) +
   월별 상세 시트 18개(컨테이너별 박스 구성·적재율).

## 4. 시나리오 기능

목표 적재율을 65% / 70% / 75%로 바꿨을 때의 월별·법인별·총 컨테이너 수를 항상 함께
계산해 비교합니다. 비교 대상 적재율 목록은 `config/container.json`의 `scenarioRates`로
변경할 수 있습니다. 슬라이더로 임의 적재율(예: 68%)의 본 산출도 즉시 확인 가능합니다.

## 5. 실제 데이터 적용 시 컬럼 맞추는 법

SAP에서 내려받은 엑셀을 그대로 쓰려면 3.2의 컬럼명과 일치시키면 됩니다.

1. **생산계획**: 첫 시트에 `법인`, `모델명` 컬럼과 월별 수량 컬럼(`YYYY-MM` 텍스트)을 두세요.
   - 월 헤더가 날짜 서식(예: `2026년 9월`, `Sep-26`)이면 텍스트 `2026-09`로 바꿔야 합니다.
   - 선적 리드타임을 반영하려면 월 컬럼을 생산월이 아닌 **선적 요청월** 기준으로 배치하세요.
2. **모델-박스 구성**: 모델·박스 조합 1건당 1행. 모델명이 생산계획의 모델명과 정확히
   일치해야 합니다(공백 주의 — 앞뒤 공백은 자동 제거).
3. **박스 마스터**: 혼적 그룹 값이 실무의 "같이 실을 수 있는 박스 묶음"과 일치하도록
   그룹 코드를 부여하세요. 그룹이 하나뿐이면 모든 박스 혼적 허용과 동일하게 동작합니다.
4. **컨테이너 규격·적재율 변경**: `config/container.json` 수정 (타입 추가도 가능 — 예: 20ft).
5. 업로드 시 모델/박스코드 불일치는 화면 상단에 검증 오류로 표시됩니다.

## 8. 한계와 확장

**한계**

- FFD는 근사 알고리즘으로 최적해 대비 컨테이너가 다소 많을 수 있습니다(통상 수 % 이내).
- 부피·중량 한도 기반 산출로, 실제 3차원 배치(치수 간섭·적층 단수·팔레트 방향)는
  검증하지 않습니다. 적재율 파라미터가 이 여유분을 흡수한다고 가정합니다.
- 혼적 규칙을 "동일 그룹" 단일 조건으로 단순화했습니다. 실무 규칙(그룹 간 부분 허용,
  컨테이너당 최대 박스 수 등)이 확인되면 `packContainers`의 제약 부분만 확장하면 됩니다.

**확장 방향** (기획자 Day01 게시물 연계)

- 과거 컨테이너 실적 업로드 → 예측 vs 실적 비교로 적재율 파라미터 보정.
- 컨테이너/RoRo **운임 단가**와 미사용 **페널티 단가** 입력 → 시나리오별
  원가·페널티 절감 효과 시각화(적재율 상향 시 절감액 등).
- 선적 리드타임(법인별 오프셋) 입력 필드 및 생산월→선적 요청월 자동 변환.
- 20ft 혼용, 컨테이너 타입별 최적 믹스 산출.

# 개발일지 — 브라질/인도법인 CKD 컨테이너 수량 산출 자동화 (hd-project04)

- 프로젝트: CKD 컨테이너 수량 산출 자동화 (계산 엔진 + 시각화)
- 기획: 김은수 (생성형 AI 업무자동화 전문가과정 1차수)
- 개발 기간: 2026-08-21
- 저장소: https://github.com/aebonlee/hd-project04

---

## 1. 요구사항 분석

현재 CKD 선적 담당자가 **과거 실적 감각**으로 컨테이너 수량을 예측 → 과다 시 미사용 페널티, 과소 시 선적 불가·법인 매출 실패가 발생한다. 이를 다음 계산 체계로 자동화한다.

```
18개월 생산계획(법인별 엑셀) × 모델별 CKD 박스 구성
  → 월별·법인별 박스 종류별 필요 수량
  → 40ft 컨테이너 적재 규칙(혼적 그룹, 적재율 70%) 반영 조합 산출
  → 월별 필요 컨테이너 수 → 물류팀 전달용 엑셀
```

지시서 지침: **UI보다 계산 로직의 정확성 우선**, 박스 규격·혼적 규칙은 확인 전이므로 **설정 파일로 분리**해 추후 교체 가능하게.

## 2. 설계 결정

| 결정 | 이유 |
|---|---|
| 계산 엔진(`js/engine.js`)을 순수 UMD 모듈로 분리 | 브라우저·Node 겸용 → 단위 테스트로 산출 규칙 검증 |
| 2단계 산출: 단순 부피식(1차) + FFD bin-packing(2차) | 1차는 빠른 추정·검증 기준선, 2차는 혼적 규칙 반영 실제 소요량 |
| First-Fit Decreasing 근사 채택 | 최적해 NP-hard. FFD는 구현 단순·설명 가능·상한 보장으로 업무용으로 적절 (한계는 README 명시) |
| 모든 규칙을 `config/container.json`으로 외부화 | 40ft/40HC 규격·적재율·이월 정책을 코드 수정 없이 변경 |
| 남는 박스 기본 정책 = 당월 추가 확보, 이월은 옵션 | 기획서 9번 미확정 질문 → 가정을 명시하고 플래그로 전환 가능하게 |
| 단일 HTML UI (SheetJS + Chart.js) | 설치 없이 실행 (기획서 옵션 B), 엑셀 입출력 필수 요건 충족 |

## 3. 구현 내역

1. **계산 엔진**: 박스 집계(`aggregateBoxes`), 단순 산출(`simpleEstimate`), FFD 패킹(`packContainers` — 같은 혼적 그룹만 혼적, 부피·중량 한도 = 규격×적재율, 컨테이너별 적재 내역 생성), 종합 계산(`calculate` — 이월 옵션 포함), 시나리오 비교(`runScenarios` — 65/70/75%), 입력 검증.
2. **웹 UI**: 엑셀 3종 업로드(생산계획 다중 선택 지원) + 샘플 데이터 버튼, 법인별×월별 18개월 차트, 박스 종류별 물량, 시나리오 비교 차트, 월별 소요 표(1차/2차/실적재율), 컨테이너별 적재 구성 내역(법인 탭 + 월별 접기), 적재율 슬라이더 즉시 재계산, 물류팀 전달용 엑셀 내보내기(요약 + 월별 상세).
3. **샘플 데이터**: `make_samples.py` — 모델 6개(법인당 3개), 박스 7종(혼적 그룹 G1/G2), 2026-09~2028-02 18개월 계획. 엑셀 4종과 임베디드 데모를 동일 데이터로 생성.

## 4. 테스트 및 검증

- `node test/engine.test.js` — **10개 테스트 통과**: 박스 집계, 단순 산출, **수기 계산 FFD 케이스**(P/Q/R 박스, 7CBM/700kg 한도 → 3대 vs 단순식 2대), 중량 한도 케이스, 이월 수량 보존, 시나리오 단조성(적재율↑ → 컨테이너↓), 샘플 전체 무결성
- headless 렌더링 검증: 샘플 기준 70%에서 **2,069대(브라질 972 + 인도 1,097)**, 75% 조정 시 1,906대 즉시 재계산, 콘솔 에러 0건
